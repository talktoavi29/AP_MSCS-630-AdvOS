Introduction
Coming to modern systems, the operating systems that are used are extremely efficient. Not just running or power a system, but managing processes is an extremely important task that these operating systems conduct that make it possible for our modern systems to run multiple programs in seamless manner as if the programs are all consuming the system resources all at once but in the background, it’s the OS in action. Two of the most important jobs the OS does are managing processes and running scheduling algorithm.
Process Management
1. Process States
Let’s imaging a person is using their computer and they are playing a YouTube tutorial on Data Mining techniques and have their VSCode open where they are coding and running the code that they learn from the tutorial. On the browser, they have Gmail, Outlook, and some other few tabs open. The YouTube tutorial talks about something they don’t understand so they open a new tab and start looking for that specific item before they move ahead with rest of the tutorial. Here, the person does one task at a time, but they are constantly shifting their current priority. These programs that run on their computer are all processes. These processes have different states depending on what the person is doing currently - New, Ready, Running, Blocked (or Waiting), and Terminated. As these processes execute, they transition through five distinct states:
•	New: When the user first launches VSCode or opens a new tab, the process is being created and initialized by the operating system.
•	Ready: When a process is loaded into memory but is waiting for the CPU to become available, it sits in the Ready state. For example, the browser background tabs are ready to run but are waiting for their turn.
•	Running: When a process is selected to be the one actively executing and utilizing resources, its put into Running state, where it actively utilizes the CPU to execute instructions. This is analogous to the user actively typing code in VSCode.
•	Waiting (Blocked): If the process needs to wait for an external event, such as reading a large file from the disk or waiting for the user to click a button, it transitions to the Blocked state. It remains here until the event occurs, releasing the CPU for other tasks.
•	Terminated: Finally, when the process finishes its task or encounters an unrecoverable error, it moves to the Terminated state and is cleaned up by the system.
2. Process Control Block (PCB)
A common question here arises, how the operating system manages and keeps track of these processes. OSes use Process Control Block (PCB) for tracking these processes and it is also alternatively called process tables. PCB stores all the information about all the processes separately. This allows the operating system to change the processes states and jump on to next process and when it is back to a specific process, the execution can be resumed from exactly where it was paused. This mechanism is called context switching.
The process information stored in this process table includes Process ID (PID), which uniquely identifies a process. It also stores program counter for the OS to know which process to run after which one and the values of CPU registers. It also includes information about memory management such as pointers, process state and open files.
3. Process Creation and Termination
Operating systems provide system calls to create and end processes. In Unix-like systems, a new process from another process can be created using fork() and this new process is called child process, which is initially a copy of the parent. This child process then calls exec() to replace its code and start running a different program. The parent can call wait() to pause until the child finishes. For example, a program needs to run some resource analysis and one method calls another method. The return value of the called method is needed for the process to complete. So another process is created, the original method goes into wait() state, the child process can exec() and once the child process is complete, the parent process can go back to running state  and continue the rest of the execution.
Processes can end in two main ways:
•	Voluntary termination, when a process finishes normally or exits after handling an expected error.
•	Involuntary termination, when it is killed because of a serious error or by another process (for example, using a kill signal).
This model gives the OS control over what runs, when it runs, and how it is cleaned up afterward.
4. Threads
A thread is the smallest unit of execution inside a process. A process has its own private memory space, but multiple threads within that process share the same code, data, and global variables. Each thread still has its own program counter and stack, so it can follow its own path of execution.
Using threads has several advantages:
•	Lower overhead than creating full processes, because threads share memory and other resources.
•	Better parallelism on multi-core CPUs, since different threads can run at the same time on different cores.
•	Improved responsiveness. For example, a web server can handle many client requests with different threads, or a GUI application can keep the interface responsive in one thread while another thread performs heavy background work.
CPU Scheduling Algorithms
1. First-Come, First-Served (FCFS)
FCFS is the algorithm in which, whichever process arrives first gets the CPU first, and it keeps running until it finishes or blocks for I/O. But, with FCFS comes The Convoy Effect, meaning if a very long process gets the CPU first, all the other shorter jobs that arrive later have to wait behind it. This can eventually provide a poor performance to the overall system.
2. Shortest Job Next (SJN)
In SJN, the focus is on reducing the average waiting time for the processes, so that the problems from FCFS is avoided. The choice of the next process depends on which process has the least expected CPU bursts. By doing the short jobs first, the algorithm can give excellent average waiting times. The downside is starvation. If short processes keep arriving, longer processes can be pushed back indefinitely and may barely run at all. Another practical issue is that it is hard for the OS to know exactly how long a process will run before it starts.
3. Round-Robin (RR)
Round-Robin is a popular algorithm in which each process is allowed a fixed CPU time called the time quantum. This is a popular algorithm in Apache Kafka from a comparative analysis perspective, where messages are evenly distributed across all available partitions of topic and has a similar conceptual application in case of operating systems. The scheduler cycles through the ready queue, giving each process a turn. If the process is not completed within the time quantum, the priority moves to the next process, and this process that went into wait state goes to the end of the queue and waits for its turn again.
The length of the time quantum is important:
•	If it is too large, Round-Robin starts to behave like FCFS.
•	If it is too small, the system spends too much time on context switches, reducing overall efficiency.
Despite this trade-off, Round-Robin usually provides much better responsiveness for interactive users than FCFS.
4. Priority Scheduling
Priority is a very straight-forward concept. Each process in different states have their own priority and the OS executes the process based-on the highest priority identified. Priorities can be set by the operating system (for example, based on resource usage) or by users and applications.
This approach introduces some challenges:
•	Priority inversion, where a low-priority process holds a resource needed by a high-priority one, causing the high-priority process to wait.
•	Indefinite blocking (starvation), where low-priority processes may rarely or never get CPU time.
A common solution is aging, where the priority of a process gradually increases the longer it waits, ensuring that it eventually gets to run.
